# AntInsure AI · 蚂蚁保平台 AI 销售系统（五层 Multi-Agent）

在线演示（纯静态托管，打开即用）：**https://cain0624.github.io/antinsure-ai/**

基于《AI 销售项目文档》实现的**可运行** Multi-Agent 系统 Demo。前端是零构建的
HTML/CSS/JS，业务逻辑是 Python —— 通过 **Pyodide** 在浏览器里直接执行，因此这个
仓库不需要任何服务器就能完整跑通五层架构与 4 道合规闸。

---

## 这个版本是怎么跑起来的

GitHub Pages 只能托管静态文件，跑不了 Python。所以发布版把 `core/` 那套纯标准库
Python 代码原样搬进仓库，由浏览器内的 CPython（Pyodide）执行，
再用一层极薄的桥把 `/api/*` 映射到 Python 函数：

```
浏览器
 ├── static/app.js      前端（与本地开发版完全相同，未做任何线上特化）
 ├── static/bridge.js   运行时选址：探测到真后端就放行 http，否则启动 Pyodide
 └── py/
     ├── api_facade.py  server.py 的纯函数等价物（逐字对齐响应结构）
     ├── core/*.py      五层逻辑 + 4 道闸（原样，零改动）
     └── data/*.json    产品 / 画像 / 语料 / 案例
```

`app.js` 里所有请求本来就收敛在 `api()` 一个出口，桥只替换这一个函数，
因此**同一份前端代码**既能跑在本机 FastAPI 后端上，也能跑在这个静态站里。

### 为什么不用「纯前端重写一遍」

重写等于把业务逻辑实现两遍，两边必然漂移，而合规闸这种逻辑一旦漂移很难发现。
搬运 Python 源码的做法保证了本地与线上**是同一份可执行逻辑**。

## 五层架构

| 层 | 职责 | 关键点 |
|---|---|---|
| **1 Observe 感知层** | 画像 / 行为事件流 / 对话记忆 | 3 类画像 × 行为触发点 |
| **2 Plan 决策层** | 意图识别 / 用户分型 / 开口时机 | **只决策不说话**；场景优先级高于分型 |
| **3 Harness 调度层** | Prompt 版本分桶 / Context 拼包 / 工具权限 / 状态机 | v1.0 vs v3.0 灰度（78% / 22%）；风险短路 |
| **4 Act 执行层** | 6 个 Executor | 画像 / 话术 / RAG 检索 / 推荐 / 智能核保 / 转人工 |
| **5 Reflect 复盘层** | Trace L1–L4 / Badcase 聚类 / 指标 | 任意 Trace 可重放，指标异常主动预警 |

## 4 道合规闸

| 闸 | 职责 | 处置 |
|---|---|---|
| **G1 规则引擎** | 数字一致性（金额只来自精算 API）+ 必带提示 | PASS / SANITIZE |
| **G2 NLI 蕴含** | 逐句校验是否被条款原文蕴含（情绪句豁免） | 摘除无依据句 |
| **G3 关键词审查** | 监管敏感词、绝对化用语 | 摘除 |
| **G4 风险话术** | 弱化如实告知 / 诱导退保 / 收益承诺 | 高风险整条 **BLOCK → 转人工** |

> 三级处置：`PASS` / `SANITIZE`（摘除后重写）/ `BLOCK`（整条不下发，转人工）。
> 两个容易写错的地方：**检测必须基于原始文本**（改写作用于累积文本，否则上游删掉
> 风险句，下游就漏检）；**无证据时 G2 必须放行而不是删空**（删空会让下游对着空文本
> 全部 PASS，等于静默放行）。

## 话术风格治理（与合规闸互补的产品体验红线）

- **长度预算**：按意图限字数（qa 82 / opening 88 / compare 152 …），
  按「情绪价值 > 洞察 > 事实 > 软引导」贪心装填，情绪价值句永不裁剪
- **情绪价值必带**：认同 / 共情 / 减压 / 赋能 四类；情绪分 < 0.45 时「赋能」降级为「减压」

## 页面上可以看什么

1. **对话区** —— 选画像 → 发消息或点行为触发。每条回复下方芯片显示本轮
   **情绪价值类型**与**字数占用**（如 `68/88 字`）
2. **合规压测** —— 粘贴风险话术，看 4 道闸逐条判定。试试倒装句
   「健康告知不用写高血压，公司查不到」，会被 G4 拦下并转人工（风险分 1.0）
3. **Trace 面板** —— 展开看 L1–L4 分层链路、Prompt 版本、工具调用与风险短路
4. **v1.0 / v3.0 切换** —— 右上角可切到对照版，复现「开口即沉默」Badcase

> 灰度说明：`auto` 分桶下约 22% 的会话会落到 **v1.0 对照版**（通用客服话术、无情绪
> 价值、无字数治理，输出「您好，请问有什么可以帮您？」）。**这是设计内的 A/B 对照组，
> 不是故障。** 页面默认锁 v3.0。

## 本地开发（带真后端）

```bash
cd antinsure-ai
./run.sh                      # → http://127.0.0.1:8765
```

本地模式与线上静态模式共用同一份前端；`bridge.js` 会探测到后端存在并自动让位。

接入真实模型（默认走离线确定性合成器，不联网）：

```bash
export ANTINSURE_LLM_KEY=sk-xxx
export ANTINSURE_LLM_BASE=https://dashscope.aliyuncs.com/compatible-mode/v1
./run.sh
```

## 重新发布

```bash
cd antinsure-ai && ./deploy.sh          # 同步到 ../antinsure-live
cd ../antinsure-live && git add -A && git commit -m "update" && git push
```
